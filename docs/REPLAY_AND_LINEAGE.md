# 재실행·재개와 근거 연결 검사

2026-11-07 보수. 기존 금융 판단·원문 읽기 기록·STR 순위는 유지한다. 이 변경은 반복 가능한 파일 실행 경로이며 상시 에이전트 서버나 자동 조사 일정이 아니다.

## 실행하는 순서

기존 ID를 유지한 변경 배치와 해당 연구의 연결 명세를 먼저 작성한다. 중요한 주장에는 원문 ID, 가설에는 대안과 판별 관측, 행동에는 연결된 가설·주장·원래 결정 위치를 지정한다. [명세 형식](../schemas/research_lineage.md)을 따른다. 과거 실행을 고친 것처럼 덮어쓰지 않고 새 run ID와 새 명세를 만든다.

저장소 루트에서 다음 순서로 실행한다. 아래 예시는 금융 원장을 변경하지 않는 이번 유지보수 실행이다.

```sh
python scripts/run_pipeline.py prepare --run-id 20261107-maintenance --batch runs/2026-11-07-maintenance-batch.json --lineage data/research_lineage_20261106.json
python scripts/run_pipeline.py apply --plan runs/pipeline/20261107-maintenance/plan.json
python scripts/research.py validate
python scripts/lineage.py --manifest data/research_lineage_20261106.json
python -m unittest discover -s tests -v
```

`prepare`는 제안된 원장과 연결을 검사한 뒤 입력 배치·참조 파일의 해시·원장 변경 전후 해시를 고정한다. `apply`는 저장→연결 재검사→생성물 재생성→최종 검증→완료 순서로 체크포인트를 남긴다. 완료 표시는 검증 후에만 기록한다. 같은 입력의 재실행은 ID와 변경 이력을 추가하지 않는다. 완료된 실행도 입력과 현재 원장이 일치하는지 다시 검사한다.

고정 배치는 LF 줄바꿈의 정확한 바이트로 보존하며 Git 줄바꿈 변환도 제외한다. 고정 후 편집기 등으로 줄바꿈만 바뀌어도 재개 전에 중단하고 원래 바이트 복원을 안내한다. 다른 참조 입력의 비교는 CRLF/LF 차이만 정규화한다. 파일 내용 변경을 허용한다는 의미는 아니다.

## 중단됐을 때

- 같은 `apply` 명령을 다시 실행한다. 원장 저장 중 끊겼으면 고정한 배치와 복구 저널로 이어간다. 검증·생성물·체크포인트 단계에서 끊겼어도 다시 확인한다.
- 현재 원장이나 고정 입력이 다른 작업으로 바뀌었으면 덮어쓰지 않고 중단한다. 기존 실행과 변경 파일을 보존하고 차이를 확인한 다음 새 run을 준비한다.
- 미완료 원장 작업이 있을 때 일반 조회·검색·검증·재생성은 중단한다. 해당 원래 배치를 먼저 재개한다. 다른 배치로 회복을 시도하지 않는다.
- 잠금 파일을 삭제해서 실행을 강행하지 않는다. 프로세스가 끝나면 운영체제 잠금은 풀리며 파일이 남는 것은 정상이다.

이 잠금은 **같은 로컬 체크아웃에서 이 도구를 쓰는 프로세스**를 조정한다. OneDrive 동기화·다른 기기의 작업·수동 편집까지 막는 분산 잠금이 아니다. 실행 중 외부 수정이 발견되면 충돌로 멈춘다. 복구 저널의 바이트 상태가 다른 체크아웃에서는 강제로 이어가지 않는다. 별도 체크아웃에선 상태를 대조하고 새 실행을 준비한다.

`research.py ingest`는 기존 호출 방식도 유지하며 원장 복구를 제공한다. 다만 별도의 가설·행동 연결 검사는 `run_pipeline.py`와 명세를 함께 사용할 때 수행한다. 연구 갱신의 기본 진입점은 새 runner다.

## 이번 연결의 범위

[명세](../data/research_lineage_20261106.json)는 기존 11월6일 연구의 읽기 기록33건 → 주장 C-421~C-432 → 초기 가설6개 → BNK·교보·한화의 우선 행동9개를 연결한다. 원문·주장·가설·행동의 존재, 중복·고립 참조, 주장 유형, 읽기 상태, 원본 위치와 해시, 대안·관측을 검사한다.

원래 읽기 기록5건의 `read_status` 누락은 원본을 바꾸지 않고 명세의 교정 기록으로 보완했다. 당시 기록된 선택 읽기 범위에 근거해 `selected_sections`로 한정하며 새로 읽었다거나 전문을 읽었다고 표시하지 않는다.

연결 검사는 **기록과 참조의 일관성**을 확인한다. 출처가 실제로 주장을 충분히 뒷받침하는지, 인과 해석이 맞는지, 미래 방향이 유효한지는 금융·경제 원리 검토와 반대 사례 검토가 계속 필요하다. 기존432개 주장 전체와 모든 과거 보고서의 행동 연결을 소급 검증한 것은 아니다.
