# 금융 근거연구에 쓸 AI 개발 방식 조사 — 2026-11-02

이 조사는 **금융환경 자료 수집 → 근거 해석 → 기업·직무 적용 → 반증·병합 → 변경 추적**에 필요한 기능을 기준으로 12개 저장소를 선정했다. GitHub 전체에서 그달 가장 인기 있었던 프로젝트를 전수 조사한 순위표가 아니다. 12개 후보의 실제 월별 스타 이력과 공식 릴리스는 확인했으며, 전체 GitHub 월별 순위는 미검증이다. 설치·서비스 변경·원격 쓰기와 성능 시험은 하지 않았다.

## 먼저 내릴 판단

가장 먼저 채택할 것은 **불변 원문, 파생 위키, 근거 ID, 정정 로그, 같은 과제에 대한 평가**라는 운영 방식이다. 실행 환경·검색 시스템을 한꺼번에 늘릴 근거는 아직 없다. 기존 WeKnora 이용 상태를 확인한 뒤 최신 기능을 비교하고, 부족한 부분에 QMD·Docling·평가 도구를 소규모로 시험한다. 관계·시간 질의가 실제로 막힐 때 LightRAG 또는 Graphiti를 추가한다. 아래 채택·시험·보류는 설계 권고이며 도입 완료 상태가 아니다.

‘graph engineering’은 하나의 표준 제품명으로 다루지 않았다. **업무 실행의 상태·분기를 잇는 그래프**는 LangGraph, **문서 속 엔터티·관계를 잇는 그래프**는 LightRAG/GraphRAG, **시간에 따라 바뀌는 사실·출처를 잇는 그래프**는 Graphiti로 구분한다. LLM Wiki의 페이지 연결도 법적 권리·인과관계를 검증한 그래프와 같지 않다.

## 월별 스타 이력을 읽는 법

공식 [GitHub star history 문서](https://docs.github.com/en/rest/activity/starring?apiVersion=2022-11-28#get-repository-star-history)를 확인하고 저장소별 공개 GET 응답을 직접 수집했다. API는 주별 total과 일요일부터 시작하는 7개 days를 제공한다. week epoch를 UTC 날짜 레이블로 풀어 월별 합계를 계산했다. **문서는 주·일 경계가 UTC와 일치한다고 보장하지 않으므로 한국시간 월별 정확한 순증으로 읽으면 안 된다.** 취소된 스타의 과거 반영 방식도 해당 문서만으로 확정하지 않았다. 표 제목은 ‘현재 조회한 공식 history의 생성일 기준 월별 스타 수’로 제한한다.

11월은 11월2일 조회 시점까지의 부분 기간이다. 0은 실제 API에 포함된 날짜들의 합이 0인 경우이며, 저장소 생성 전이나 데이터 결측은 —/null로 남긴다. 후보 12개에서 이미 존재한 달의 이력 범위는 모두 확보했다. **673개 주의 날짜 연속성, 중복, 7일 길이, 비음수 정수, 일별 합=주별 합을 확인했다.** 월별 수치가 당시 인기도·사용량·품질·금융 분석 성능을 증명하지는 않는다.

## 도구별 적용 판단

### NousResearch/hermes-agent

공식 README는 기억·스킬·도구·일정·격리된 하위 에이전트를 묶은 실행 환경을 설명한다. 10월 v0.22.5 릴리스에는 위임 백엔드와 모델별 라우팅, Windows 갱신 등의 변경이 포함된다. 기억과 스킬 갱신은 원문 출처 검증을 대신하지 않는다. [공식 저장소](https://github.com/NousResearch/hermes-agent)

- 목적: 여러 조사 역할의 실행·재개·스킬 재사용
- 비용: 상시 프로세스, 모델·검색 비용, 권한과 기억 관리
- 출처·정정: 별도 불변 근거 원장과 정정 검증 필요
- 중복: 현재 실행 환경·Deep Agents·WeKnora 에이전트와 기능 중복
- 현재 역할 분담 방식 대비 기대: 반복 조사 실행을 한 런타임에 모을 가능성; 정확도 우위 미측정
- 판정: **시험** — 현재 방식 대비 재개 성공률과 검수 시간을 비교한 뒤 선택

### HKUDS/LightRAG

엔터티·관계와 벡터를 결합하며 증분 갱신, 문서 삭제 후 관련 그래프 재구성, 인용을 설명한다. 2026년 5월 계열에서 다중 형식 분석을 통합했고 최신 v1.5.7은 별도 질의 화면과 그래프 우선 입력 등을 추가했다. 저비용·고품질 주장은 실제 금융 문서로 재검증해야 한다. [공식 저장소](https://github.com/HKUDS/LightRAG)

- 목적: 기업·규제·계약·상품 관계를 여러 문서에 걸쳐 검색
- 비용: 관계 추출 LLM 호출과 그래프·벡터 인덱스 운영
- 출처·정정: 원문 ID와 추출 관계 연결을 검증하고 삭제·정정 영향 검사
- 중복: WeKnora/RAGFlow 그래프 검색과 중복 가능
- 현재 역할 분담 방식 대비 기대: 단편 검색이 놓치는 연결을 찾을 가능성; 인과 추론 보장은 아님
- 판정: **시험** — 하이브리드 검색이 실패하는 다문서 질문에서만 추가 효과 측정

### microsoft/graphrag

2024년부터 이어진 연구 프로젝트다. 공식 README는 현재 유지보수 단계이며 새 기능·새 PR 수용을 중단하고 필요한 버그·의존성 수정을 수행한다고 명시한다. v3.3.0은 SQLite 성능 수정이다. 문서 전체의 주제 구조 탐색에 적합하지만 인덱싱 비용을 별도로 고려해야 한다. [공식 저장소](https://github.com/microsoft/graphrag)

## 최소 비교 시험

기준선은 현재 구상한 역할 분담과 근거 카드 방식이다. 이미 쓰는 검색·문서 저장소가 있으면 이를 먼저 측정한다. 같은 원문·질문·모델·시간 범위에 대해 (1) 기준선, (2) 위키 갱신 규칙만 추가, (3) 하이브리드 검색 추가, (4) 그래프 추가를 단계별로 비교한다. 서로 다른 장점을 한 번에 묶어 어느 변화가 효과를 냈는지 알 수 없게 만들지 않는다.

평가 질문은 발표일/시행일 구분, 협약/집행 구분, 수정 공시 반영, 같은 기업의 다른 법인 구분, 표의 단위·각주, 토큰 이동/매매/환매/은행현금 구분, 상충 근거, 모르는 값 유지 등을 포함한다. 출처 정확성·인용 구간 일치·정정 전파·근거 없는 결론·중복 사건·재실행 비용·사람 검수 시간을 기록한다. 튜닝용과 최종 비교용 질문을 분리한다. 그래프가 더 그럴듯한 답을 만드는 것만으로 채택하지 않는다.

## 갱신 사양과 남은 한계

재수집은 `python scripts/ai_stars.py refresh --output <새 스냅샷 경로>`로 명시적으로 실행한다. 공개 GET의 상태·실패를 기록하고 기존 스냅샷을 덮어쓰지 않는다. 집계 재검증은 PIPELINE.md의 명령을 따른다. 실패·생성 전·부분 기간을 0 또는 완전한 달로 바꾸지 않는다.

이번 완료 범위는 12개 목적 후보의 공식 원문·현재 누적 스타·월별 history·최신 릴리스 비교다. **전체 GitHub 월별 인기 프로젝트 발굴·순위, 현지 설치 버전, 실제 금융 문서 성능·비용 우위는 미확인**이다. 후보군 밖의 최근 프로젝트를 놓쳤을 수 있으므로 이 결과를 전수 순위로 확대하지 않는다.



## 이번 저장소에 적용한 범위

근거 원장, 출처별 카드, 주제 위키, 원문–주장–주제 연결, 정정 전후 보존과 형식 검증을 구현했다. 실제 실행 하네스는 현재 호스트의 하위 에이전트 기능을 사용했다. 위에 비교한 12개 도구의 설치·업그레이드는 수행하지 않았다. 기본 검색·명시적 연결은 후속 비교의 기준선이며 상용 GraphRAG 또는 임베딩 RAG를 구축했다는 의미가 아니다.

최근 자료에 대한 가중은 수치 점수로 꾸미지 않고 의사결정 순서에 적용했다. 최근 90일의 공식 기능·안정성·유지보수 변경을 우선 확인하고, 현재 목적 적합성·출처 추적·운영 부담을 다음 기준으로 삼는다. 월별 인기 수치는 보조 정보다. 1월 기능과 10월 최신판이 같은 문제를 해결하면 최신 검증판을 시험 대상으로 삼는다.
