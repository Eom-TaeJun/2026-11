# 국가 수요에서 그룹 사업을 발굴하는 에이전트 작업 순서

사용 목적은 BNK금융지주·교보그룹·한화그룹의 고객 업무를 경제·금융·기술 변화에 연결하는 것이다. 국가의 인구·시장규모를 해당 회사의 유료 고객으로 바꾸지 않는다. 현재 가용한 호스트의 다중 에이전트 기능을 사용한다. 이 파일은 실행 지침이며 상시 에이전트나 자동 수집 일정이 아니다.

## 입력

README, docs/RESEARCH_MANDATE.md, reports/22~26의 정확한 README 링크, data/group_country_opportunities.json, 대상 STR 결정, 원문 source/claim 카드와 최신 실행 기록부터 읽는다. 국가별 규제 원장은 2026-11-02 기준이며 추가 읽은 조문만 개별 확인일을 갱신한다. 공식 발표·회사 주장·해석·가설·미확인을 나눈다.

## 여덟 역할과 의존 순서

| 역할 | 입력 질문 | 산출물·완료 조건 |
|---|---|---|
| 국가·고객 수요 수집 | 누가 어떤 보장·지급·조달 의무를 갖는가, 현재 대안은 무엇인가 | 공식 통계의 모집단·시점·분모, 현지 상품·서비스·경쟁의 공개 원문과 읽은 절 |
| 회사·법인 신호 수집 | 그룹이 실제 가진 고객 계약·판매망·권한·자본·기능은 무엇인가 | 법인·상대방·국가·날짜·단계별 연결; 지분과 실제 업무 구별 |
| 해석·요약 | 자료가 무엇을 말하고 무엇을 입증하지 않는가 | source 카드, claim 종류, 미관측·접근 실패·이전 판단과 차이 |
| 고객·현금 흐름 설계 | 고객 한 건이 누구와 계약하고 돈·권리는 어디로 가는가 | 지급자·통화·권리·수수료·최종현금·실패복구·법인 손익 |
| 교수형 경제 추론 | 권한·레일이 모두 성립한 뒤에도 어떤 희소성과 경쟁이 남는가 | 기본/강한 변화/반대 가설, 유동성·인수·가격·정보·자본 배분 및 판별 관측. 실제 교수 견해 대리 아님 |
| 목적 적용·사업 설계 | 기존+AI와 온체인+AI 중 무엇이 같은 업무를 개선하는가 | 외부 지급자·고객접점·경쟁 견적·총비용·수익귀속·90일 초기 검증 및 장기 관측 |
| 독립 검증 | 인가·발표·출시·반복사용·수익이 혼합됐는가 | 주요 원문 표집 재확인, 계산·권리·손익 검토, 오류와 수정 여부. 동의 수는 증거가 아님 |
| 병합·보존 | 기존 원장과 어디가 달라졌는가 | 단일 작성자 ingest, 변경 이유·history, 인덱스·맵·원격 게시 및 재조회 |

국가별 독립 자료 수집을 병렬 배정하고 해석→검토→병합은 의존 순서를 지킨다. 작업마다 질문·입력·쓰기 허용 경로·완료 조건을 전달한다. 공유 원장은 병합 담당자만 편집한다.

## 사업 카드 필수값

특정 고객/업무 → 국가·통화·기간 → 기존 대안 → 확인한 기반 → 실제 계약 법인 → 권리·현금 경로 → 지급자·비용·손실 → AI 역할 → 온체인의 증분 편익 → 경쟁 반응 → 확대/중단 관측. 계약·고객수·요율·예산·이익은 미확인이면 null이다.

예금·보험료·AUM·토큰 거래량은 이익이 아니다. 보험자·은행·증권·운용·기술사·산업법인의 손익을 나누고 실제 연결범위 내부거래만 제거한다. 외부 공급자가 더 나으면 그 대안을 남긴다. 외부 AI의 설명·견적·실행·철회 권한과 고객 승인도 구분한다.

## 검증·게시

기존 scripts/research.py의 ingest → build → validate와 tests를 따른다. 공식 원문 표집과 미확인 한계를 별도로 기록한다. 파일·출처·주장·상대 링크·null·개인정보 경계를 확인한 뒤 기존 main의 예상 SHA를 확인하여 게시한다. 원격 파일과 트리를 다시 읽어 저장을 검증한다. 실제 고객 시험·외부 연락·주문·금융거래는 이 연구 절차에서 수행하지 않는다.
