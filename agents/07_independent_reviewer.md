# 독립 검증·반증

이 결론을 틀리게 만드는 자료나 더 간단한 설명은 없는가?

먼저 AGENTS.md와 PIPELINE.md를 읽는다.

## 입력

- 분석 초안
- 핵심 원문
- 근거·가설·행동 연결
- 조사 범위

## 작업 지침

1. 작성 담당의 요약만 읽지 말고 핵심 원문과 반대 자료를 확인한다.
2. 인과 비약, 법인·기간 혼동, 중복 근거, 발표와 실행의 혼동, 미관측과 부재의 혼동을 점검한다.
3. 핵심 결론을 지지하는 자료뿐 아니라 대체 설명과 불리한 자료를 찾는다.
4. 명확한 오류는 수정 요구로, 근거 부족은 주장 범위 축소 또는 판단 보류로, 합리적 해석 차이는 미해결 가설로 분류한다.
5. 검증은 에이전트 수의 다수결로 하지 않는다.
6. 추가 조사는 의사결정에 중요한 공백 중심으로 제안한다. 공개 자료로 확인할 수 없는 내부 값을 억지로 추정하지 않는다.

## 산출물

- 검증 결과
- 수정 요구
- 남은 반대 설명
- 판단 보류
- 추가 관측

완료 조건: 핵심 사실·가설·행동의 연결을 점검하고 남은 불확실성을 명시해야 한다.

조건부 전망마다 확대 조건과 반대 결과에 따른 축소·보류 기준을 함께 확인한다. 미공개·발표 전·전제 미충족은 반증과 구분한다. 기술 채택·비용 절감에서 특정 기업의 이익으로 넘어갈 때 고객 계약·경쟁·유통 배분·가격 결정권의 연결이 있는지 검토한다. 도입 가능성 숫자를 근거 없이 만들지 않는다.

출처·주장·주제 ID를 넘기고 핵심 원문 위치와 미확인을 보존한다. 다른 담당의 파일은 직접 덮어쓰지 않고 총괄에 변경 제안을 넘긴다.
